## End-to-end verification against LiveKit Cloud (2026-09-09, local worker, new code)

Method: the new code ran as a LOCAL worker registered under a unique agent name (so production
dispatches could never reach it), driven by a scripted caller (`livekit.rtc` participant publishing
OpenAI-TTS-synthesized lines) in a `test-web-*` room for tenant "Make It AI" — 3 runs. Absolute
latencies include a Singapore laptop → US/EU vendor hops and are NOT Railway numbers; the stage
metrics below are what transfer.

| Observation | Result |
|---|---|
| Runtime fillers | spoken only on slow tools ("Okay, pulling that address up." during validate_address; "Let me get your details down." during capture_lead); NONE on the cached check_slot turn, which answered in 1.6 s voice-to-voice |
| Typing sound | second agent track `background_audio` carried energy only inside tool windows |
| Backchannel | "mm-hmm" during agent speech did not interrupt (runs 1 and 3; run 2's interruption was a harness bug — see note) |
| Same-turn goodbye | goodbye ChatMessage + end_call in one turn; caller disconnected 1.27 s after the last agent audio (1 s RTP-drain sleep + API) |
| Adaptive interruption | `adaptive interruption detector initialized` / session created (threshold 0.656) |
| Turn detector | `turn-detector-v1` cloud transport, no fallback |
| ElevenLabs TTS TTFB | **0.09-0.11 s** with an in-account voice (vs 0.9 s median on the deployed OpenAI fallback) |
| LLM TTFT | 0.66-0.94 s (prompt 6.4k tokens, ~6.1k cached on turn 1 — the cache warm lands) |
| EOT | confident turns commit at 0.58 s; but 2-3 of 5 synthetic-caller turns scored p=0.07-0.39 (< 0.56) and waited the full max_delay |

**Findings that need action outside this change set**
1. Railway `ELEVEN_API_KEY` was the ElevenLabs key **ID** and was rejected → every
   production call runs on OpenAI TTS (0.9 s TTFB, greeting 5-8 s to unmute). The accepted `sk_` secret
   is the main repo's `.env.local` `ELEVENLABS_API_KEY`.
2. None of the three configured voices (Alexandra `kdmDKE6EkgrWrrykO9Qt`, Eryn, Cassidy) are in the
   ElevenLabs account's My Voices → the websocket closes with 1008 and the FallbackAdapter burns ~7 s
   before switching. Add them to My Voices (or pick in-account voices) before expecting ElevenLabs audio.
3. Railway has `VOCO_MAX_ENDPOINTING_DELAY_S=1.2` set. KEEP it for now: it caps the audio detector's
   low-confidence wait at today's value (the code default 2.5 s would otherwise apply). Re-evaluate
   with real-caller `eot prediction` debug lines; `VOCO_TURN_DETECTOR_UNLIKELY_THRESHOLD` (new) lowers
   the confidence bar if genuine turns keep scoring below the SDK default.
4. Harness note: any code that calls `logging.getLogger("livekit.agents")` BEFORE importing the SDK
   gets a plain Logger and the SDK's `logger.trace` then raises inside the interruption path
   (`_disable_vad_interruption`), silently re-enabling VAD interruptions. agent.py touches that
   logger only after the import, so production is unaffected.
5. UAT observations: the model used the caller's name outside the readback ("Thanks, Leroy") once,
   and asked for the block number three times when the scripted caller never answered — both worth
   watching on real calls.

## ElevenLabs key hardening (added before the push)

The owner re-keyed Railway under the name `ELEVENLABS_API_KEY` with a RESTRICTED key (Text to Speech +
Voices:Read, no User:Read) and the three mapped voices are still not in the account. Three guards were
added so that configuration cannot silently degrade calls:
- `agent.py` accepts `ELEVENLABS_API_KEY` as an alias for `ELEVEN_API_KEY` (plugin, preflight and the
  `__main__` boot check all read the latter; without the alias the deploy would refuse to start).
- The key preflight treats a 401 `missing_permissions` / `user_read` answer as *inconclusive* (valid key,
  ElevenLabs-first), not as a rejected key.
- `prewarm()` fetches the account's voice list (`/v1/voices`, Voices:Read) and `_build_tts()` swaps a mapped
  voice that is missing from the account for `VOCO_ELEVEN_FALLBACK_VOICE_ID` (default: premade "Sarah",
  present in every account), logging an ERROR that names the fix. Verified live against the restricted key.

## Deploy checklist

1. Railway builds from `pyproject.toml`; no new env vars are required (every new flag defaults to
   the recommended value). Set `ELEVEN_API_KEY` to the `sk_` secret and add the three voices to My
   Voices first, otherwise calls stay on OpenAI TTS. Keep `VOCO_MAX_ENDPOINTING_DELAY_S=1.2`. `LIVEKIT_API_KEY/SECRET` already on the service authenticate LiveKit
   Inference for the turn detector and the adaptive interruption model.
2. Watch the first calls' logs for:
   - `turn detector: audio inference.TurnDetector version=v1 model=turn-detector-v1`
   - absence of `cloud turn detector failed (...); falling back to local mini model` (if present,
     the worker cannot reach LiveKit Inference — calls still work on v1-mini, ~108 MB RAM/process)
   - `turn_handling endpointing=dynamic/0.30-2.50s interruption=adaptive min_words=2`
   - `background audio started thinking_sound=True ambient=False`
   - `instructions refreshed with caller context` (repeat callers) and `unmute waited Nms` (should be ~0)
   - `turn_metrics ... eot_delay=` (expect a drop vs the 1.5.7 baseline)
3. Live UAT scripts: (a) a fast availability question — no filler should be spoken, typing audible
   briefly; (b) an address — the filler line should play only if the lookup is slow; (c) a booking —
   one filler, "still working" only if >6 s; (d) say "mm-hmm" while the agent talks — it must keep
   talking; say "no, wait" — it must stop; (e) end the call — goodbye completes, then the line drops
   with no second goodbye; (f) a Spanish caller — fillers in Spanish.
4. Recordings now include the typing sound (the composite egress mixes all tracks).

## Rollback (no redeploy)

| Symptom | Flag |
|---|---|
| Agent cuts callers off / talks over them | `VOCO_TURN_DETECTOR=text` (old detector + 0.4/1.2 s) or raise `VOCO_MIN_ENDPOINTING_DELAY_S` |
| Agent ignores real interruptions | `VOCO_MIN_INTERRUPTION_WORDS=1` or `VOCO_INTERRUPTION_MODE=vad` |
| Fillers feel wrong | `VOCO_TOOL_FILLERS=false` (typing sound stays) / `VOCO_TOOL_FILLER_DELAY_S=1.0` |
| Typing sound unwanted | `VOCO_THINKING_SOUND=false` |
| Caller-context injection issues | `VOCO_CONTEXT_READY_TIMEOUT_S=0` unmutes right after the greeting |
| Keyterms suspected of hurting STT | `VOCO_STT_KEYTERMS=false` |
